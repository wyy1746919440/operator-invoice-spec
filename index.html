运营商开票管理 PC 端 · 需求说明

适用范围：运营商侧 PC 后台「申请开票」「发票抬头」两个页面 · 交互基线：与 OS 端（内部后台）保持一致

一、范围与背景

在范围内① 申请开票页（平台给客户开票）：资金明细筛选 → 选择认证主体 → 填写开票信息 → 提交；② 发票抬头页：抬头列表 + 新增/编辑/删除；③ 开票详情页：申请快照只读展示；④ 发票详情页（客户给平台开票）：查看平台开票资料 + 上传发票。
不在范围内开票管理列表页（由业务方自行设计，本文档不涉及）；开票历史页。
交互基线PC 端为单页操作，不做步骤条；先筛选搜索，再选择认证主体，最后填写开票信息；表单在上/下的顺序跟随操作顺序，按钮左置，返回/保存右下角。
与 OS 端差异去掉「申请信息」区块（客户名称 / 申请类型 / 开票主体 / 合同附件 / 备注）。运营商侧无该概念，开票主体由认证主体承担。

二、系统与配置依赖

交易类型由 OS 端配置，选项可增、减、改名；运营商 PC 端只消费配置结果，不做硬编码枚举。「全部」为系统固定项，与具体类型互斥。
单次开票金额下限由 OS 端配置，当前值 500 元；配置变更时前端校验与提示文案自动跟随，不在前端写死。
费用明细项由交易流水产生，随交易类型配置联动。

三、术语

认证主体资金流水的归属主体，是开票的起点；一个开票申请只能对应一个认证主体。
发票抬头开票时使用的名称。取值恒等于认证主体，不可修改。
费用明细认证主体下的交易明细行（费用明细项 / 笔数 / 金额）。
账期费用所属月份，按月开票，不支持按日区间。

四、页面一：申请开票

3.1 布局顺序

  • 页面自上而下：面包屑 → 资金明细卡片（筛选区 + 明细表格）→ 开票信息卡片（表单）→ 右下角操作区（保存）。
  • 两块顺序不可颠倒：先筛出数据，才能选主体，最后才能填抬头。

3.2 资金明细 · 筛选区

交易类型多选下拉。选项由 OS 配置（当前示例：支付手续费 / 算法识别费 / 平台使用费 / 提现手续费 / 供应链收入 / 退款手续费返还），可增可减，前端不写死。
选中任意具体类型时自动取消「全部」；全部取消时自动回到「全部」。
收起态文案：全选显示「全部」；选 1–2 项显示具体名称；选 3 项以上显示「已选 N 项」。
账期时间起止月份（YYYY-MM）。起、止均只能选择 2026-06 及之后的月份，且结束月份 ≥ 开始月份。
按钮搜索（主按钮，执行后刷新明细）、重置（恢复全部类型 + 默认账期 + 清空已选主体）。
筛选失效处理若某认证主体的明细被筛选条件全部排除，该主体不出列表，且若已被选中则自动取消选中。
R1 账期下限固定为 2026 年 6 月，早于该月份的账期不可选。

3.3 资金明细 · 表格

分组结构按认证主体分组，每组一行组头 + 展开该主体的费用明细行。
列选择（单选） / 认证主体 / 费用明细项 / 笔数 / 金额（元）。
组头内容单选按钮 + 主体名称 + 「共 N 笔，可开票金额 ¥X」，笔数与金额随筛选结果变化。
金额样式负数（退款类）标红；金额右对齐。
表尾「已选认证主体：X」「合计金额：¥X（N 笔）」，随筛选与选中结果联动。
提示条卡片底部文字：订单的认证主体需和发票抬头为同一个；单次开票金额最少为 500 元，无法达到开票金额，可联系售后～

3.4 开票信息 · 表单

发票抬头必填选中认证主体后自动带出该主体名称；不可修改（未维护抬头的主体也带出名称，仅下方资料留空待填）。未选主体时控件置灰，占位「请先选择认证主体」。
抬头类型企业 / 个人，默认个人。已维护抬头的主体带出记录值；未维护时可自行选择。
发票类型必填普票 / 专票，默认普票。
企业资料单位税号 / 单位地址 / 单位电话 / 开户银行 / 银行账户，仅抬头类型为企业时展示；已维护抬头的按记录带出，未维护的留空由用户填写。
邮箱地址必填用于接收发票。
备注选填
R2 发票抬头恒等于认证主体，任何情况下都不可在申请页修改。
R3 抬头类型为个人时，发票类型只能为普票，专票置灰不可选；切换为个人时若已选专票，自动回落为普票。

3.5 保存与校验

操作区右下角：保存（主按钮）。
校验顺序① 未选认证主体 → 拦截；② 可开票金额 < 500 元 → 拦截。
金额口径按筛选后的明细行计算（笔数、金额均随当前筛选条件）。
成功态提交成功弹窗：展示开票金额与笔数，提示 1-3 个工作日内开具并发送至邮箱。
R4 单次开票金额下限由 OS 配置（当前 500 元），低于该值不允许提交；配置变更时校验与提示文案自动跟随。
R5 拦截提示文案：单次开票金额最少为 500 元，当前认证主体可开票金额 ¥X，无法达到开票金额，可联系售后～

五、页面二：发票抬头

5.1 列表

按钮位置左上：新增发票抬头（主按钮）。
列发票抬头 / 抬头类型 / 单位税号 / 单位地址 / 单位电话 / 开户银行 / 银行账户 / 操作（编辑、删除）。
展示规则抬头类型为个人时，企业资料五项均显示「-」。
空态列表为空时显示「真的没有了~」。
删除二次确认后删除。

5.2 新增 / 编辑弹窗

字段与小程序「发票详情」一致：发票抬头、抬头类型、单位税号、单位地址、单位电话、开户银行、银行账户。
发票抬头必填占位「请输入发票抬头」。
抬头类型必填企业 / 个人，默认企业。
单位税号企业必填占位「输入税号或营业执照代码」。
单位地址企业必填≤100 字，占位「100字以内，不能为空」。
单位电话企业必填≤20 字，占位「20字以内，不能为空」。
开户银行 / 账户选填占位「请输入」。
显隐抬头类型为个人时，企业资料五字段整体隐藏。
保存校验不通过时在弹窗内显示红字提示，不关闭弹窗；校验通过后关闭并回写列表。
R6 个人抬头不采集税号/地址/电话/开户行/账户；企业抬头必须采集税号、地址、电话。

六、页面三：开票详情

6.1 定位

  • 入口：开票管理列表页 → 操作列「详情」。页面为只读，不可编辑。

6.2 状态横幅（置顶）

位置面包屑下方、所有内容之上，常驻置顶（与小程序/OS 详情一致）。
样式待审核=橙色、已开票=绿色、已驳回=红色，文案：开票状态：X。
已驳回追加展示驳回原因；右侧提供「重新开票」入口，跳转申请开票页并带出本次信息。
关闭横幅右侧提供 ✕，可手动收起。
R11 状态只出现在顶部横幅，不重复出现在下方字段区。

6.3 发票信息（只读）

布局多列字段网格（参考 OS 详情），不使用纵向长列表。
字段开票金额（红色加粗）/ 抬头类型 / 发票抬头 / 发票类型 / 单位税号 / 单位地址 / 单位电话 / 开户银行 / 银行账户 / 申请人 / 申请时间 / 备注。不展示认证主体（与小程序一致）。
字段来源取自提交时的快照；个人抬头不展示企业资料字段。
空值备注等选填项为空时展示「—」。

6.4 资金明细（只读）

列交易类型 / 费用明细项 / 账期 / 笔数 / 金额（元）。
合计行表格底部总计行（加粗、浅底）：合计笔数与合计金额，与开票金额一致。
样式负数（退款类）标红；金额右对齐。
明细口径与提交时一致，不随后续配置变更而变化。

6.5 操作区

右下角返回（无导出明细）。
R9 详情页为提交数据的快照，交易类型配置变更后不回改历史详情。

七、页面四：发票详情（客户给平台开票）

7.1 场景

  • 除平台给客户开票外，还存在客户给平台开票的方向：平台向运营商发起开票请求，运营商按平台开票资料开具发票并上传，由平台审核。
  • 与小程序「发票详情」页字段、状态保持一致。

7.2 状态横幅（置顶）

状态流转待开票 → 待平台审核 → 已完成；平台驳回后回到待开票（可重新上传）。
待开票橙色横幅：开票状态：待开票｜需您给大黄鹅开票，为避免影响提现，请于 7 天内上传发票（剩余天数动态显示）。
待平台审核蓝色横幅：已收到发票，平台审核中。
已驳回红色横幅：展示驳回原因，可重新上传。
已完成绿色横幅。
R12 上传时限 7 天（自平台发起开票请求起算），横幅展示剩余天数；超时影响提现的口径以平台通知为准。

7.3 开票信息（平台资料，只读）

布局多列字段网格，支持「收起/展开更多信息」。
字段开票金额（红色加粗）/ 发票抬头（平台抬头，固定）/ 发票类型 / 税号 / 单位地址 / 单位电话 / 开户银行 / 银行账户 / 备注。
来源平台开票资料由 OS 端配置，自动带出、不可修改；空值展示「--」。
R13 发票抬头恒为平台抬头（大黄鹅），客户不可修改。

7.4 上传发票

文件必填支持 jpg / png / pdf，单个不超过 10M；可删除重传。
发票号码必填8-20 位。
开票日期必填日期选择。
发票类型必填普票 / 专票，提交后回显到开票信息。
提交校验不通过在表单下方红字提示；通过后横幅切换为「待平台审核」，上传区隐藏，不可重复提交；驳回后恢复上传入口。

7.5 开票明细（只读）

标题行右侧展示「共 N 笔，总金额 ¥X」（金额红色）。
列费用明细项 / 金额（元）/ 税率；表尾总计行。
口径与发起请求时一致，不随后续配置变更而变化。

八、规则汇总

R1账期只能选择 2026-06 及之后，结束月份 ≥ 开始月份。
R2发票抬头恒等于认证主体，不可修改。
R3个人抬头 → 发票类型只能普票，专票置灰。
R4单次开票金额 ≥ 500 元。
R5金额不足时的拦截文案（见 3.5）。
R6抬头页字段规则：个人不采集企业资料，企业必填税号/地址/电话。
R9开票详情为提交快照，交易类型等配置变更不回改历史详情。
R10交易类型选项、单次开票金额下限均由 OS 端配置，前端不硬编码。
R11详情页状态横幅置顶：按状态变色；已驳回展示原因并提供「重新开票」。
R12客户开票上传时限 7 天，横幅展示剩余天数。
R13客户开票的发票抬头恒为平台抬头，不可修改；平台开票资料由 OS 配置自动带出。
R7账期提示文案：仅支持 2026 年 6 月及之后的账期（常驻在账期控件后）。
R8发票类型提示文案：抬头类型为个人时，仅支持开具普票（仅个人抬头时显示）。
